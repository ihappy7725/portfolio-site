# 정주연 포트폴리오 사이트 (portfolio-site)

HTML, CSS, JavaScript만으로 만든 한 페이지 포트폴리오입니다. 빌드 과정이 없어서 파일을 고치고 새로고침하면 바로 반영됩니다.

## 사이트의 방향

현재 기준은 **2026-11-15**입니다. 이 문서의 현재 구성은 이날 사용자가 승인한 내용이며, 이전 설계와 검토 과정은 아래 변경 이력과 [CONTENT_REVIEW.md](CONTENT_REVIEW.md)에 보관합니다.

국제 통상과 정책에 관한 자료를 읽고, 교역 통계와 함께 살펴보는 도구를 만드는 장기 포트폴리오입니다. 영문 브라우저 탭 제목의 분야 표기는 **Global Trade & Policy Research**이며, 메인 문구는 **“무역 뉴스를 읽고, 관련 정책과 교역 통계를 한눈에 살펴보는 도구를 만듭니다.”**입니다. 개발자 채용용 기술 목록보다 관심 질문, 자료를 다루는 과정과 본인의 기여를 중심으로 구성합니다.

2027년 RA 및 GR 지원을 준비하고, 2028년 가을 미국 국제관계 또는 공공정책 대학원 진학을 목표로 합니다. 지원과 진학은 앞으로의 목표이며 현재의 직위나 입학 실적으로 표시하지 않습니다. 영어와 TOEFL 준비, 2026년 8월부터 12월까지의 무역 AX마스터 과정 수강과 12월 18일 수료 예정도 진행 상태에 맞춰 관리합니다.

대표 프로젝트는 개발 중인 **Trade Data Lab**, 팀 프로젝트 **AXPORT**, **Hanjungsun** 순서입니다. 프로젝트 설명은 배경과 문제, 자료와 방법, 전략적 또는 정책적 시사점을 앞에 두고, 실제 구현 과정, AI와 본인의 역할, 결과, 한계와 회고는 상세에 보존합니다. 기존 Trade News Room은 Trade Data Lab의 구성 요소이자 이전 개인 프로젝트 기록으로 연결합니다.

About에서는 학업 배경, 실무 경험과 Trade Data Lab 개발을 구분합니다. 공공서비스 AI 상담 챗봇 캡스톤은 별도로 착수할 예정인 활동이며 Trade Data Lab의 구성 요소나 이미 완성한 결과물로 표시하지 않습니다. 취업용 PPT나 PDF가 필요하면 같은 자료에서 지원 목적에 맞는 부분을 별도로 구성합니다.

## 폴더 구조

```
portfolio-site/
├── index.html        ← 페이지 뼈대 (보통 고칠 일 없음)
├── css/style.css     ← 디자인 (색은 맨 위 :root 변수에서 변경)
├── js/content.js     ← 모든 문구, 링크, 프로필 사진 경로 ⭐ 주로 여기만 수정
├── js/main.js        ← content.js를 읽어 화면을 그리는 코드
├── CONTENT_REVIEW.md ← 참고 자료 비교, 내용 검토 결과와 다음 보완 순서
├── prompts/          ← 다른 프로젝트에서 실행할 개발 요청문
└── assets/           ← 프로필 사진 등 이미지와 공개용 프로젝트 자료
    └── projects/
        ├── axport/axport-us-sample-report.html ← 현재 연결한 가상 기업 보고서 원본
        ├── axport/axport-us-sample-report.pdf  ← 이전 보고서 보관본
        ├── hanjungsun/ ← HOME 시연 발췌와 홍보영상
        └── tradenews/ ← 통계 그래프와 조달 비중 시뮬레이터의 실제 화면
```

## 화면과 데이터 구조

화면 순서는 **첫 화면 → About → Projects → Experience → Now → Notes → Contact**입니다. Notes에 글이 없으면 해당 섹션과 상단 메뉴가 모두 숨겨져 Now 다음에 Contact가 이어집니다.

`js/content.js`의 `SITE.i18n` 아래에서 `ko`, `en`, `zh-Hans`, `zh-Hant`, `ja` 다섯 언어를 관리합니다. `js/main.js`가 선택한 언어의 데이터를 읽어 화면을 구성합니다. 번체는 대만식 표현을 사용합니다.

| 위치 | 관리 항목과 표시 방식 |
|---|---|
| 첫 화면 | `hero.headline`에 승인된 메인 문구를 저장합니다. 사진 프레임 없이 문구와 관심 분야를 배치하며, 세 범주의 역량을 실제 사용 범위에 맞춰 소개합니다. |
| 상단바 | `SITE.profile.headerName`의 이름, 가운데 메뉴와 언어 선택을 표시합니다. 언어 선택은 현재 언어 버튼 하나로 접혀 있고, 처음 방문하면 한국어입니다. 마우스, 터치와 키보드로 목록을 열 수 있습니다. URL의 `lang`과 선택한 언어의 저장 동작은 유지합니다. |
| 페이지 제목과 검색용 설명 | `meta.title`은 브라우저 탭 제목입니다. 검색용 설명은 `hero.headline` 뒤에 `meta.description`을 붙여 만들며 언어 전환 시 함께 갱신합니다. 메인 문구를 바꿀 때 `index.html`의 기본 한국어 설명도 함께 수정합니다. |
| About | 학업, 실무 경험과 도구 개발, 향후 활동을 구분합니다. 학력과 교육, 언어와 자격, 활용 도구의 상세는 독립된 접이식 바로 관리합니다. 취미는 표시하지 않습니다. |
| 프로젝트 카드 | 가로 카드를 한 줄에 하나씩 배치합니다. 핵심 질문, 배경과 문제, 자료와 방법, 전략적 또는 정책적 시사점과 개인 기여를 읽을 수 있습니다. 좁은 화면에서는 세 열의 설명이 한 열로 바뀝니다. |
| 프로젝트의 세 단계 설명 | `caseStudy.background`, `caseStudy.methodology`, `caseStudy.implications`에서 관리합니다. 기존 `process`, `ai`, `outcome`, `limits`, `lessons`와 `role`, `note`도 상세에 보존합니다. 시사점은 현재의 해석 또는 후속 질문이며 당시 수행하지 않은 분석을 새로 주장하지 않습니다. |
| Trade Data Lab | 공통 id는 `tradedatalab`입니다. 도구 전체가 완성되거나 독립 실행 주소가 생긴 것으로 표시하지 않습니다. 구성 요소의 상태와 공개 가능 주소를 각각 관리합니다. |
| 이전 Trade News Room | Trade Data Lab의 `legacyProject`에 원문과 역할, AI 활용, 결과, 한계, 회고, 자료와 학습실 목록을 보존합니다. 현재 공개된 학습실 다섯 개는 펼쳐 볼 수 있습니다. |
| 구성 요소의 링크 | `SITE.links.projectComponents`에서 Trade News Room, Policyline과 Tradeweave의 실제 주소를 관리합니다. 다른 구성 요소처럼 주소가 없는 경우에는 링크를 만들지 않습니다. 전체 Trade Data Lab 주소와 개별 구성 요소 주소를 혼용하지 않습니다. |
| 추가 자료 | `materials`에는 자료 id와 다국어 버튼 문구를, `SITE.links.projectMaterials`에는 같은 id의 주소를 저장합니다. 한정선의 소개 홈페이지, HOME 시연 발췌와 홍보영상, 기존 Trade News Room의 통계 및 시뮬레이터 화면을 유지합니다. 자료가 한국어이면 다른 언어의 버튼에서도 안내합니다. |
| 프로젝트 자료 링크 | `SITE.links.projects`는 독립 실행 사이트, `SITE.links.reports`는 공개 보고서 주소입니다. 현재 AXPORT에 한국어 HTML 보고서가 연결되어 있습니다. 주소가 비어 있으면 버튼을 표시하지 않습니다. |
| 실무 경험 | `experience.items[].cases`에서 `buyers`와 `verification`을 관리합니다. 인턴 기간, 역할, 관리 범위와 역량을 먼저 보여주고, 담당 업무와 사례는 토글로 펼칩니다. 각 사례의 `workflow`에 작업 흐름, `caption`에 공개 범위를 담고, 바이어 사례의 `comparison.headers`와 `comparison.rows`에 익명 재구성한 비교 틀을 저장합니다. 기존 `caseText`도 데이터에 보존합니다. |
| 실무 사례의 공개 범위 | 국내외 바이어 프로그램 20사례는 한국을 포함한 조사 및 비교 범위입니다. 익명화하고 재구성한 비교 틀과 근거 대조 흐름을 사용하며 원본 회사 자료는 게시하지 않습니다. 해외 미디어 파트너 18개사는 관리 범위이고, 전부 계약 또는 이행 완료한 수가 아닙니다. STK 9개 매체와 TechCon 7개 매체의 게재 근거는 행사별 범위로 구분합니다. |
| Now | 기준일, 강조 문장, 진행 중인 일과 관심 분야를 관리합니다. 2027년 지원과 2028년 가을 진학, TOEFL 준비 등 목표와 현재 수행 중인 활동을 구분합니다. |
| Notes | `notes.items`의 실제 글 목록을 최신 날짜순으로 표시합니다. 선택한 언어의 목록이 비어 있으면 섹션과 메뉴를 함께 숨기며 다른 언어의 글을 대신 표시하지 않습니다. |
| Contact | 이메일 주소와 연락폼을 두 열로 표시합니다. `contact.form`에서 다국어 문구를 관리합니다. 제출하면 `mailto:`로 기본 이메일 앱의 작성창을 열며 최종 보내기는 이메일 앱에서 진행합니다. 작성 내용은 언어 전환 중 현재 탭의 메모리에만 유지합니다. |

### Trade Data Lab의 구성과 상태

| 구성 요소 | 현재 표시 범위 |
|---|---|
| Trade News Room | 이미 공개된 뉴스 기반 학습 프로토타입. 기존 학습실 다섯 개와 실제 사이트 주소를 연결합니다. |
| Policyline | 동작하는 구성 서비스로 소개하고 사용자가 제공한 실행 주소를 연결합니다. |
| Tradeweave | 동작하는 구성 서비스로 소개하고 사용자가 제공한 실행 주소를 연결합니다. 공개 주소의 이름이 전체 Trade Data Lab을 뜻하지는 않습니다. |
| Fact Desk | Trade News Room 안에서 계획한 기능입니다. 기존 규칙 기반 안내 챗봇을 이 기능의 구현 완료로 표시하지 않습니다. |
| Report Plain | 계획 단계로 표시합니다. |
| Trade Notebook | 계획 단계로 표시하며, 포트폴리오의 Notes에 실제 글이 생긴 것으로 간주하지 않습니다. |

### 전체 프로젝트와 서비스 주소의 구분

`SITE.links.projects.tradedatalab`은 빈 문자열로 유지하므로 전체 프로젝트의 실행 버튼은 표시하지 않습니다. 구성 서비스의 실제 주소는 다음과 같습니다.

| `SITE.links.projectComponents` 키 | 서비스 | 실제 주소 |
|---|---|---|
| `tradenews` | Trade News Room | <https://trade-news-room.vercel.app/> |
| `policyline` | Policyline | <https://policy-line-eight.vercel.app/> |
| `tradeweave` | Tradeweave | <https://trade-data-lab.vercel.app/> |

특히 `trade-data-lab.vercel.app`은 사용자가 제공한 **Tradeweave 서비스의 주소**입니다. 도메인 이름을 보고 Trade Data Lab 전체 주소로 옮겨 연결하지 않습니다.

기존 Trade News Room의 실행 주소는 <https://trade-news-room.vercel.app/>입니다. 이 주소는 해당 구성 요소의 주소이며 Trade Data Lab 전체의 공개 주소가 아닙니다. 학습실은 `#learn-urea`처럼 `#learn-아이디`로 바로 열 수 있고, 목록은 보존된 Trade News Room의 `rooms`에서 관리합니다. 해당 사이트의 학습 메모와 퀴즈 응답은 포트폴리오 Notes와 별개이며, 그 사이트를 연 브라우저에 저장됩니다.

한정선의 영문 표기는 **Hanjungsun**입니다. 링크 연결을 위해 내부 id와 키인 `hanjeongseon`은 유지합니다. AXPORT의 분석 엔진과 전체 대시보드, 한정선의 전체 대시보드는 팀 결과물이며 개인 기여 범위와 구분합니다. KOTRA 재무제표 수업 과제는 원문 검토 후 사용자가 승인한 결정에 따라 다섯 언어의 공개 목록에서 제외했습니다. 과제 자체와 검토 과정은 기록으로 남기며, 보강된 정책 연구나 검증된 분석 성과로 소개하지 않습니다.

## 자주 하는 수정

| 하고 싶은 일 | 방법 |
|---|---|
| 문구 고치기 | `js/content.js`에서 `ko`, `en`, `zh-Hans`, `zh-Hant`, `ja` 다섯 곳의 같은 항목을 함께 수정 |
| 메인 문구 고치기 | 다섯 언어의 `hero.headline`을 함께 수정 |
| 문장과 제목 줄바꿈 고치기 | `hero.headlineBreakAfter`와 제목의 줄바꿈 기준에는 원문에 실제로 들어 있는 의미 단위를 사용합니다. 줄을 짧게 만들기 위해 문구를 임의로 줄이지 않습니다. 다섯 언어 모두 구절과 문장 단위로 자연스럽게 이어지도록 데스크톱과 모바일에서 확인합니다. |
| 페이지 제목과 검색용 설명 고치기 | 다섯 언어의 `meta.title`, `meta.description`을 함께 수정합니다. 검색용 설명 앞부분은 메인 문구를 그대로 사용합니다. 메인 문구를 바꿀 때 `index.html`의 기본 한국어 description도 함께 맞춥니다. |
| 소개글 고치기 | 다섯 언어의 `about.title`, `about.body`를 함께 수정합니다. 이미 수행한 일, 현재 학습 중인 내용과 장기적인 목표를 구분합니다. |
| 상단 이름과 분야 표기 고치기 | 상단 이름은 `SITE.profile.headerName`, 영문 브라우저 탭의 분야 표기는 `SITE.i18n.en.meta.title`에서 관리합니다. 다른 언어의 탭 제목과 본문의 이름도 해당 언어의 `meta`, `hero`에서 함께 확인합니다. `SITE.profile.photo`는 과거 설정의 보관용이며 현재 사진 프레임은 표시하지 않습니다. |
| GitHub, LinkedIn 버튼 | `SITE.links.github`, `SITE.links.linkedin`에 주소 입력 (비워두면 버튼이 숨겨짐) |
| 프로젝트 링크 버튼 | `SITE.links.projects`의 해당 id에 실제 주소를 입력합니다. Trade Data Lab의 구성 요소는 `SITE.links.projectComponents`를 사용하며 전체 프로젝트와 개별 구성 요소를 구분합니다. |
| 공개 보고서 연결 | `assets`에 공개할 HTML 또는 PDF를 넣고 `SITE.links.reports`의 해당 프로젝트 id에 상대 경로를 입력합니다. 다섯 언어의 `projects.labels.report`에서 파일 형식과 언어 안내를 함께 맞춥니다. 파일을 연결하기 전에 공개 범위와 보고서 언어를 확인합니다. |
| 새 프로젝트 추가 | 다섯 언어의 `projects.items`에 같은 `id`로 항목을 하나씩 추가 |
| 프로젝트 핵심 질문 고치기 | 다섯 언어의 같은 프로젝트에서 `question`을 함께 수정 |
| 내가 맡은 핵심 고치기 | 다섯 언어의 같은 프로젝트에서 `contribution`을 함께 수정하고 기존 `role`과 사실관계가 맞는지 확인 |

## Notes에 새 글 추가하기

현재 다섯 언어의 `notes.items`는 모두 빈 배열 `[]`입니다. 실제 글을 준비한 뒤 다음 순서로 추가합니다. 목록을 등록해도 글의 본문 페이지가 자동으로 만들어지지는 않으므로 본문은 별도로 준비합니다.

1. `js/content.js`에서 한국어 `ko` 영역의 `notes`를 찾습니다. 프로젝트의 `note`와 구분합니다.
2. `items: []` 안에 글 객체를 넣습니다. 아래 코드는 입력 형식이며, 표시용 예시 글이 아닙니다. 제목, 날짜와 요약을 실제 내용으로 바꾼 뒤 저장합니다.

   ```js
   items: [
     {
       title: "실제 글의 제목으로 교체",
       date: "YYYY-MM-DD",
       summary: "실제 글의 한 줄 요약으로 교체",
       tags: [],
       link: ""
     }
   ]
   ```

3. 각 필드를 다음 기준으로 작성합니다.

   | 필드 | 작성 방법 |
   |---|---|
   | `title` | 실제 글의 제목 |
   | `date` | 실제 글의 날짜를 `YYYY-MM-DD` 형식으로 입력합니다. 월과 일도 두 자리로 맞춰야 최신 날짜순 정렬이 정확합니다. |
   | `summary` | 글의 내용을 설명하는 한 줄 요약 |
   | `tags` | 태그 문자열의 배열입니다. 태그가 없으면 `[]`를 유지합니다. |
   | `link` | 실제 본문으로 연결되는 `https://` 또는 `http://` 주소, 혹은 사이트 내부 HTML 파일의 상대 경로입니다. 상대 경로는 `index.html` 위치를 기준으로 작성합니다. 빈 문자열 `""`이면 글 정보는 표시하고 제목의 링크만 생략합니다. |

4. `en`, `zh-Hans`, `zh-Hant`, `ja`의 `notes.items`에도 같은 글을 추가합니다. 제목, 요약과 태그는 각 언어로 함께 작성하며, 번체는 대만식 표현을 사용합니다. 날짜는 같게 유지하고, 번역된 본문이 따로 있다면 해당 언어의 링크를 연결합니다.
5. 글이 여러 개라면 객체 사이에 쉼표를 넣습니다. 입력 순서와 관계없이 날짜가 최신인 글이 먼저 표시됩니다.
6. Live Server에서 다섯 언어를 전환하며 Notes 메뉴, 글 정보와 제목 링크를 확인합니다. 현재 언어의 목록을 다시 `[]`로 비우면 그 언어의 섹션과 메뉴가 숨겨집니다.

## 로컬에서 확인하기

`index.html`을 브라우저로 바로 열어도 되고, VS Code의 Live Server 확장으로 열면 저장할 때마다 자동으로 새로고침됩니다.

1. VS Code의 확장 프로그램에서 Ritwick Dey의 **Live Server**를 설치합니다.
2. `index.html`을 열고 오른쪽 아래 **Go Live**를 누르거나, 파일을 우클릭해 **Open with Live Server**를 선택합니다.
3. 데스크톱에서 다섯 언어를 전환하며 메인 문구, 관심 분야 태그, 프로젝트 핵심 질문과 “자세히 보기” 안의 기여 설명을 확인합니다. 주소 뒤에 `?lang=ko`, `?lang=en`, `?lang=zh-Hans`, `?lang=zh-Hant`, `?lang=ja`를 붙여 각 언어로 바로 열 수도 있습니다.
4. 브라우저 개발자 도구의 기기 모드에서 너비를 **390px**로 설정하고 긴 제목과 태그의 줄바꿈, 버튼 간격, 가로 넘침을 확인합니다. Notes 메뉴가 늘어나면 좁은 화면에서 상단 메뉴를 좌우로 스크롤할 수 있습니다.
5. 글이 없는 현재 상태에서는 Now 다음에 Contact가 이어지고 빈 공간이나 Notes 메뉴가 없는지 확인합니다. 실제 글을 추가한 뒤에는 Now와 Contact 사이에 Notes가 보이고 상단 메뉴에서 이동할 수 있는지 확인합니다.
6. 상단에는 현재 언어 버튼 하나만 보이는지 확인합니다. 데스크톱에서는 마우스를 올려 목록을 열고, 모바일에서는 버튼을 눌러 언어를 고릅니다. 키보드로는 버튼에 초점을 둔 뒤 Enter 또는 아래 화살표로 열고, 위아래 화살표로 이동하며 Escape로 닫을 수 있습니다.
7. About 아래 세 개의 바가 처음에는 닫혀 있고, 오른쪽 + 또는 바 전체를 누르면 각각 독립적으로 열리는지 확인합니다. 학력, 언어와 자격, 활용 도구의 기존 내용은 펼친 안쪽에서 확인할 수 있습니다.
8. 실무 경험은 요약과 태그가 먼저 보이고 담당 업무와 사례 토글이 각각 독립적으로 열리는지 확인합니다. 바이어 비교 틀과 근거 대조 흐름, 가로 프로젝트 카드의 세 단계 설명과 보존된 상세를 확인합니다. Trade Data Lab의 구성 서비스 세 개가 각각 맞는 주소로 열리고 전체 프로젝트 버튼은 없는지, 이전 Trade News Room에서 학습실 다섯 개를 펼칠 수 있는지 확인합니다.
9. 연락폼의 필수 항목과 이메일 형식 검사를 확인합니다. 입력 후 언어를 전환하면 작성 내용은 현재 탭에서 유지됩니다. 새로고침하면 입력 내용은 초기화됩니다.
10. “이메일 작성창 열기”를 누르면 설정된 기본 이메일 앱에 받는 사람, 제목과 내용이 채워지는지 확인합니다. 실제 보내기는 이메일 앱의 보내기 버튼으로 완료합니다. 기본 이메일 앱 설정에 따라 작성창 연결 방식이 달라질 수 있습니다.

Notes의 사이트 내부 상대 링크는 Live Server나 배포된 사이트에서 확인합니다. 파일을 브라우저로 직접 연 환경에서는 해당 링크가 표시되지 않을 수 있습니다.

## 작성과 공개 원칙

- 제공한 이력과 성과만 사용하고 새로운 수치, 수상, 실적을 만들지 않는다.
- 숙련도를 퍼센트나 별점으로 표시하지 않고 실제 사용 범위로 설명한다.
- 팀 프로젝트는 팀 결과물과 내 기여 범위를 구분한다.
- 가운데점 기호는 쓰지 않는다.
- 입력하지 않은 링크는 화면에서 숨긴다.
- 문구를 수정할 때는 다섯 언어를 함께 수정하고, 번체는 대만식 표현을 사용한다.
- 이름은 한국어 정주연, 영어 Juyeon Jung, 간체 郑主缘, 번체와 일본어 鄭主緣으로 표기한다. 한정선의 영문 표기는 Hanjungsun이다.
- 핵심 질문과 기여 설명은 확인된 사실을 사용한다. 프로젝트 이후에 공부한 내용과 당시 직접 수행한 일은 구분한다. 자료를 보여주는 도구를 실증 연구, 인과 분석이나 검증된 정책 효과로 확대하지 않는다.
- 의미 단위의 자연스러운 줄바꿈은 모든 문구 수정과 화면 개편에서 계속 지킨다. 다섯 언어의 긴 제목, 문장과 버튼을 데스크톱 및 모바일에서 함께 확인하고, 줄바꿈을 맞추려고 사실이나 설명을 생략하지 않는다.
- 이력서 원본, 인턴 기록 ZIP, 내부 회사 문서, 성적표, 개인 주소와 제3자의 연락처는 공개 저장소에 복사하지 않는다. 필요한 경우 익명화하고 재구성한 비교 틀이나 작업 흐름만 게시한다.
- 실무 경험의 18개 파트너 관리 범위와 행사별 게재 확인 수, 국내외 바이어 프로그램 20사례를 서로 다른 범위로 구분한다. 광고비 비중, CTR과 ROAS의 원본 수치나 변환 수치를 검증된 성과로 게시하지 않는다.
- Trade Data Lab의 각 구성 요소는 공개됨, 개발 중, 계획 단계를 구분한다. 없는 실행 주소와 가상의 Notes를 만들지 않는다.
- 탐구 기록에는 실제 글만 추가한다.
- 프로젝트 수행 기간, 출력물의 작성일과 분석 기준일을 구분한다. AXPORT의 프로젝트 기간은 2026년 9월이며 현재 연결한 가상 기업 HTML 보고서는 작성일 2026-11-11, 분석 기준일 2026-11-10의 출력 예시다.
