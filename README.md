# 정주연 포트폴리오 사이트 (portfolio-site)

HTML, CSS, JavaScript만으로 만든 포트폴리오입니다. 실제 프로젝트와 실무 경험을 메인 페이지에 보여주며, 빌드 과정 없이 파일을 고치고 새로고침하면 바로 반영됩니다.

## 사이트의 방향

현재 기준은 **실제 프로젝트와 실무 경험 중심의 구성**입니다. 이전 설계와 검토 과정은 아래 변경 이력과 [CONTENT_REVIEW.md](CONTENT_REVIEW.md)에 보관합니다.

국제 통상과 정책에 관한 자료를 읽고, 교역 통계와 함께 살펴보는 도구를 만드는 장기 포트폴리오입니다. 영문 브라우저 탭 제목의 분야 표기는 **Global Trade & Policy Research**이며, 메인 문구는 **“중화권 이해와 국제 협업 경험을 바탕으로, 국제통상·정책 분야의 조사와 분석 역량을 쌓고 있습니다.”**입니다. 메인은 중화권 이해와 국제 협업 경험, 통상과 정책 분야의 조사 및 분석 역량을 쌓는 방향을 설명합니다. 이름 위 영문 표기, 소개 두 줄과 강점 제목은 화면에서 제외합니다. 다섯 언어의 메인과 소개, 검색 설명을 함께 관리합니다.

2027년 RA 및 GR 지원을 준비하고, 2028년 가을 미국 국제관계 또는 공공정책 대학원 진학을 목표로 합니다. 지원과 진학은 앞으로의 목표이며 현재의 직위나 입학 실적으로 표시하지 않습니다. 영어와 TOEFL 준비, 2026년 8월부터 12월까지의 무역 AX마스터 과정 수강과 12월 18일 수료 예정도 진행 상태에 맞춰 관리합니다.

대표 프로젝트는 개발 중인 **Trade Data Lab**, 팀 프로젝트 **AXPORT**, **Hanjungsun** 순서입니다. 사용자가 선택한 **짧은 카드와 펼친 상세**에 맞춰 가이드의 한 줄 요약, 문제 정의, 해결 과정, AI 적용, 결과를 나눠 보여줍니다. 기본 카드에는 설명형 제목과 유형 및 기간, 요약과 본인 역할, 짧은 문제 및 결과를 두고 상세에는 해결 과정 세 단계와 AI의 작업 및 본인의 판단과 확인 범위를 둡니다. 기존의 세 행 설명과 긴 원문은 기록으로 보존합니다.

About에서는 학업 배경, 실무 경험과 도구 제작의 연결을 세 문단으로 설명합니다. 서비스별 기능은 프로젝트에서, 공공서비스 AI 상담 챗봇 캡스톤의 착수 준비는 Now에서 안내해 중복을 줄입니다. 이 캡스톤은 Trade Data Lab의 구성 요소나 이미 완성한 결과물로 표시하지 않습니다. 취업용 PPT나 PDF가 필요하면 같은 자료에서 지원 목적에 맞는 부분을 별도로 구성합니다.

Trade Data Lab은 무역과 데이터를 주제로 여러 웹사이트와 도구를 만드는 개인 프로젝트입니다. 각 웹사이트는 서로 다른 질문과 목적에 맞춰 별도로 기획하고 제작합니다. Trade News Room, Policyline과 Tradeweave가 이 프로젝트 아래에서 동작하고 있으며, 주소는 웹사이트별로 연결합니다.

KITA 보고서 스터디는 무역 AX 교육과 병행한 활동으로 기간을 `2026.08 – 2026.12`로 표시합니다. 발제문 대시보드가 배포되면 주소를 추가할 수 있도록 연결 설정을 준비했습니다. KOTRA는 공개 재무자료를 연도별로 정리한 학부 개인 과제로 추가 활동에 복원하고, 현재의 수정 검토는 별도 학습 초안에 기록합니다.

## 폴더 구조

```
portfolio-site/
├── index.html        ← 페이지 뼈대 (보통 고칠 일 없음)
├── css/style.css     ← 공통 디자인 (색은 맨 위 :root 변수에서 변경)
├── css/note.css      ← 독립 노트 본문의 읽기 화면
├── js/content.js     ← 메인 문구, 링크와 Notes 목록 ⭐ 주로 여기만 수정
├── js/main.js        ← content.js를 읽어 화면을 그리는 코드
├── CONTENT_REVIEW.md ← 참고 자료 비교, 내용 검토 결과와 다음 보완 순서
├── prompts/          ← 다른 프로젝트에서 실행할 개발 요청문
├── notes/
│   ├── 2023-china-graphite-controls.html ← 목록에서 내린 흑연 노트 보관본
│   └── drafts/       ← 원고와 출처 대조표 보관
└── assets/           ← 이미지와 기존 프로젝트 자료 보관
    └── projects/
        ├── axport/axport-us-sample-report.html ← 가상 기업 보고서 보관본
        ├── axport/axport-us-sample-report.pdf  ← 이전 보고서 보관본
        ├── hanjungsun/ ← HOME 시연 발췌와 홍보영상
        └── tradenews/ ← 통계 그래프와 조달 비중 시뮬레이터의 실제 화면
```

## 화면과 데이터 구조

화면 순서는 **첫 화면 → About → Experience → Projects → Now → Contact**입니다. 다섯 언어의 `notes.items`는 모두 `[]`이며 Notes 섹션과 상단 메뉴는 숨깁니다. 향후 사용자가 보여주기로 정한 실제 글이 있을 때만 다시 연결합니다.

`js/content.js`의 `SITE.i18n` 아래에서 `ko`, `en`, `zh-Hans`, `zh-Hant`, `ja` 다섯 언어를 관리합니다. `js/main.js`가 선택한 언어의 데이터를 읽어 화면을 구성합니다. 번체는 대만식 표현을 사용합니다.

| 위치 | 관리 항목과 표시 방식 |
|---|---|
| 첫 화면 | `hero.headline`에 승인된 메인 문구를 저장합니다. `strengths.items`의 중화권 학업, 국제행사 협업, 통상 자료 조사 역량은 데스크톱에서 세 열로, 모바일에서 한 열로 표시하며 얇은 구분선을 사용합니다. |
| 상단바 | `SITE.profile.headerName`의 이름, 가운데 메뉴와 언어 선택을 표시합니다. 언어 선택은 현재 언어 버튼 하나로 접혀 있고, 처음 방문하면 한국어입니다. 마우스, 터치와 키보드로 목록을 열 수 있습니다. URL의 `lang`과 선택한 언어의 저장 동작은 유지합니다. |
| 페이지 제목과 검색용 설명 | `meta.title`은 브라우저 탭 제목입니다. 검색용 설명은 `hero.headline` 뒤에 `meta.description`을 붙여 만들며 언어 전환 시 함께 갱신합니다. 메인 문구를 바꿀 때 `index.html`의 기본 한국어 설명도 함께 수정합니다. |
| About | 학업, 실무 경험과 도구 개발을 연결합니다. 학력과 교육, 언어와 자격, 활용 도구의 상세는 독립된 접이식 바로 관리합니다. Python 등의 기초 학습 수준은 활용 도구 안에서 안내하고 취미는 표시하지 않습니다. |
| 프로젝트 카드 | 가로 카드를 한 줄에 하나씩 배치합니다. `presentation.title`은 이름과 용도를 함께 설명합니다. `type`과 기간 아래에 `presentation.guide`의 `summary`, `role`, `problem`, `result`를 짧게 표시합니다. 상세에는 `process` 세 단계와 `ai`의 도구, AI 지원 작업, 본인의 판단 및 확인을 표시합니다. |
| 기존 프로젝트 원문 | `question`, `problem`, `contribution`, `role`, `caseStudy`, `note`와 이전 `presentation.summary`, `presentation.contribution`, `presentation.problem`, `action`, `change`, `details`는 기록으로 보존합니다. 현재 카드 문구는 `presentation.guide`에서 관리하며 기존 장문과 별도의 한계 및 다음 단계, 회고, 보조 자료를 반복 출력하지 않습니다. |
| Trade Data Lab | 공통 id는 `tradedatalab`입니다. 여러 개별 웹 프로젝트를 만드는 개인 프로젝트로 소개하며 웹사이트별 목적과 구현 상태 및 주소를 관리합니다. |
| 이전 Trade News Room | Trade Data Lab의 `legacyProject`에 원문과 학습실 목록을 보존합니다. 포트폴리오의 중첩 상세와 학습실별 링크는 제거했으며 Trade News Room 서비스 버튼으로 이동합니다. |
| 구성 요소의 링크 | `components`에서 `status`가 `working`인 서비스만 `SITE.links.projectComponents`의 주소로 연결합니다. 사용자 선택에 따라 Trade Data Lab은 동작하는 서비스 세 개의 버튼을 유지합니다. 전체 프로젝트 주소와 개별 서비스 주소를 혼용하지 않습니다. |
| 기존 자료 보관 | `materials`, `SITE.links.projectMaterials`, `SITE.links.reports`와 기존 `assets`는 보존합니다. 보고서, 소개 홈페이지, 홍보 및 시연영상, 안내 및 시뮬레이터 화면의 자료 버튼은 표시하지 않습니다. |
| 프로젝트 실행 링크 | AXPORT와 Hanjungsun은 `SITE.links.projects`의 주소로 연결하는 대시보드 웹페이지 버튼을 하나씩 표시합니다. 주소가 비어 있으면 버튼을 표시하지 않습니다. |
| 실무 경험 | `experience.items[].cases`에서 `buyers`와 `verification`을 관리합니다. 인턴 기간, 역할, 관리 범위와 역량을 먼저 보여주고, 담당 업무와 사례는 토글로 펼칩니다. 각 사례의 `workflow`에 작업 흐름, `caption`에 공개 범위를 담고, 바이어 사례의 `comparison.headers`와 `comparison.rows`에 익명 재구성한 비교 틀을 저장합니다. 기존 `caseText`도 데이터에 보존합니다. |
| 실무 사례의 공개 범위 | 국내외 바이어 프로그램 20사례는 한국을 포함한 조사 및 비교 범위입니다. 익명화하고 재구성한 비교 틀과 근거 대조 흐름을 사용하며 원본 회사 자료는 게시하지 않습니다. 해외 미디어 파트너 18개사는 관리 범위이고, 전부 계약 또는 이행 완료한 수가 아닙니다. STK 9개 매체와 TechCon 7개 매체의 게재 근거는 행사별 범위로 구분합니다. |
| Now | `now.asOf`는 기준일, `statement`는 짧은 현재 상황, `doing`은 현재 활동입니다. `goals`의 각 항목에 `period`, `title`, `items`를 넣어 2027년 지원과 2028년 가을 진학 목표를 별도 그룹으로 표시합니다. `interests`는 오른쪽 관심 분야 태그입니다. 다섯 언어를 함께 갱신합니다. |
| Notes | 현재 다섯 언어의 `notes.items`가 비어 있어 섹션과 메뉴를 함께 숨깁니다. 실제 글을 다시 연결할 때 사용할 제목, 날짜, 요약, 태그와 링크 구조는 유지합니다. |
| Contact | 이메일 주소 아래에 연락폼을 배치합니다. 데스크톱에서는 이름과 회신 이메일을 한 행에, 모바일에서는 세로로 표시합니다. 별도의 폼 안내문은 표시하지 않고 버튼에 이메일 작성창을 여는 동작을 명시합니다. `contact.form`에서 다국어 문구를 관리합니다. 제출하면 `mailto:`로 기본 이메일 앱의 작성창을 열며 최종 보내기는 이메일 앱에서 진행합니다. 작성 내용은 언어 전환 중 현재 탭의 메모리에만 유지합니다. |

### Trade Data Lab에서 만드는 웹사이트와 구현 상태

| 구성 요소 | 현재 표시 범위 |
|---|---|
| Trade News Room | 공개된 뉴스 기반 학습 프로토타입입니다. 서비스 버튼을 연결하며 학습실별 링크는 포트폴리오에 나열하지 않습니다. |
| Policyline | 동작하는 구성 서비스로 소개하고 사용자가 제공한 실행 주소를 연결합니다. |
| Tradeweave | 동작하는 구성 서비스로 소개하고 사용자가 제공한 실행 주소를 연결합니다. 공개 주소의 이름이 전체 Trade Data Lab을 뜻하지는 않습니다. |
| Fact Desk | Trade News Room 안에서 계획한 기능이라는 기록을 데이터에 보존합니다. 서비스 버튼과 별도 구성 카드는 표시하지 않습니다. |
| Report Plain | 계획 단계라는 기록을 데이터에 보존하며 화면에 별도 구성 카드를 표시하지 않습니다. |
| Trade Notebook | 계획 단계라는 기록을 데이터에 보존하며 화면에 별도 구성 카드를 표시하지 않습니다. 포트폴리오의 Notes와도 구분합니다. |

### 전체 프로젝트와 서비스 주소의 구분

`SITE.links.projects.tradedatalab`은 빈 문자열로 유지하므로 전체 프로젝트의 실행 버튼은 표시하지 않습니다. 구성 서비스의 실제 주소는 다음과 같습니다.

| `SITE.links.projectComponents` 키 | 서비스 | 실제 주소 |
|---|---|---|
| `tradenews` | Trade News Room | <https://trade-news-room.vercel.app/> |
| `policyline` | Policyline | <https://policy-line-eight.vercel.app/> |
| `tradeweave` | Tradeweave | <https://trade-data-lab.vercel.app/> |

특히 `trade-data-lab.vercel.app`은 사용자가 제공한 **Tradeweave 서비스의 주소**입니다. 도메인 이름을 보고 Trade Data Lab 전체 주소로 옮겨 연결하지 않습니다.

기존 Trade News Room의 실행 주소는 <https://trade-news-room.vercel.app/>입니다. 이 주소는 해당 구성 요소의 주소이며 Trade Data Lab 전체의 공개 주소가 아닙니다. 기존 학습실 목록은 `legacyProject.rooms`에 보존하지만 포트폴리오에서 개별 링크를 나열하지 않습니다. 해당 사이트의 학습 메모와 퀴즈 응답은 포트폴리오 Notes와 별개이며, 그 사이트를 연 브라우저에 저장됩니다.

한정선의 영문 표기는 **Hanjungsun**입니다. 링크 연결을 위해 내부 id와 키인 `hanjeongseon`은 유지합니다. AXPORT의 분석 엔진과 전체 대시보드, 한정선의 전체 대시보드는 팀 결과물이며 개인 기여 범위와 구분합니다. KOTRA는 자산과 부채, 수입과 지출의 변화를 정리한 학부 개인 과제로 다섯 언어의 추가 활동에 복원했습니다. 과제 대상 자료는 2020~2024년이며 과제 수행 연도로 표시하지 않습니다. 오류를 고친 현재의 검토는 별도 학습 초안으로 보관합니다.

### 프로젝트의 다섯 요소 관리하기

`presentation.guide`는 가이드의 다섯 요소를 웹 카드에 맞춰 저장합니다. 기본 카드와 상세는 같은 정보를 반복하지 않도록 나눕니다.

| 요소 | 필드 | 작성 기준 |
|---|---|---|
| 한 줄 요약 | `summary`, `role` | 만든 것과 용도를 요약하고, 개인 프로젝트인지 또는 팀에서 무엇을 맡았는지 짧게 표시합니다. 제목, 유형과 기간은 기존 `presentation.title`, `type`, `period`를 사용합니다. |
| 문제 정의 | `problem` | 어떤 사용자나 검토 업무에서 무엇이 흩어져 있거나 구분하기 어려웠는지 씁니다. |
| 해결 과정 | `process` | 실제 작업 순서나 정보가 이어지는 과정을 짧은 문자열 세 개로 작성합니다. 확인되지 않은 실패와 수정 이력을 만들지 않습니다. |
| AI 적용 | `ai.tools`, `ai.assisted`, `ai.owned` | 도구 이름, AI가 지원한 작업, 본인이 정하고 검토한 일을 구분합니다. Trade Data Lab은 사용자 확인에 따라 Claude Code로 기획과 구현을 진행한 것으로 기록합니다. |
| 결과 | `result` | 실제로 확인할 수 있는 도구, 기능과 화면 구성을 씁니다. 실측하지 않은 생산성 향상이나 기업의 사업 성과로 확대하지 않습니다. |

가이드의 PPT 장수와 QR 제출 방식은 별도의 채용박람회 자료에 해당합니다. 이 사이트에 PPT 구성이나 희망 직무 표기를 추가하는 지침으로 적용하지 않습니다.

## 향후 Notes에 실제 글 연결하기

현재 다섯 언어의 `notes.items`는 모두 비어 있습니다. 섹션을 채우기 위한 글을 새로 만들지 않습니다. 사용자가 공개 목록에 연결하기로 정한 실제 글이 준비되면 다음 순서로 추가합니다. 목록 등록만으로 본문 페이지가 자동 생성되지는 않습니다.

1. `js/content.js`에서 한국어 `ko` 영역의 `notes`를 찾습니다. 프로젝트의 `note`와 구분합니다.
2. 빈 `items` 배열에 실제 글의 객체를 추가합니다. 아래 코드는 입력 형식이며 표시용 예시 글이 아닙니다. 제목, 날짜와 요약을 실제 내용으로 바꾼 뒤 저장합니다.

   ```js
   items: [
     {
       title: "실제 글의 제목으로 교체",
       date: "YYYY-MM-DD",
       summary: "실제 글의 한 줄 요약으로 교체",
       tags: [],
       link: ""
     }
   ]
   ```

3. 각 필드를 다음 기준으로 작성합니다.

   | 필드 | 작성 방법 |
   |---|---|
   | `title` | 실제 글의 제목 |
   | `date` | 실제 글의 날짜를 `YYYY-MM-DD` 형식으로 입력합니다. 월과 일도 두 자리로 맞춰야 최신 날짜순 정렬이 정확합니다. |
   | `summary` | 글의 내용을 설명하는 한 줄 요약 |
   | `tags` | 태그 문자열의 배열입니다. 태그가 없으면 `[]`를 유지합니다. |
   | `link` | 실제 본문으로 연결되는 `https://` 또는 `http://` 주소, 혹은 사이트 내부 HTML 파일의 상대 경로입니다. 상대 경로는 `index.html` 위치를 기준으로 작성합니다. 빈 문자열 `""`이면 글 정보는 표시하고 제목의 링크만 생략합니다. |

4. `en`, `zh-Hans`, `zh-Hant`, `ja`의 `notes.items`에도 같은 글을 추가합니다. 제목, 요약과 태그는 각 언어로 함께 작성하며, 번체는 대만식 표현을 사용합니다. 날짜는 같게 유지하고, 번역된 본문이 따로 있다면 해당 언어의 링크를 연결합니다.
5. 글이 여러 개라면 객체 사이에 쉼표를 넣습니다. 입력 순서와 관계없이 날짜가 최신인 글이 먼저 표시됩니다.
6. Live Server에서 다섯 언어를 전환하며 Notes 메뉴, 글 정보와 제목 링크를 확인합니다. 현재 언어의 목록을 다시 `[]`로 비우면 그 언어의 섹션과 메뉴가 숨겨집니다.

## 로컬에서 확인하기

기존 [흑연 본문 HTML](notes/2023-china-graphite-controls.html), [한국어 초안](notes/drafts/2026-11-15-graphite-controls.ko.md)과 [출처 대조표](notes/drafts/2026-11-15-graphite-controls.review.md)는 작성 기록으로 보존합니다. Notes 목록에서 내린 것이며 본문 파일이나 직접 접근 주소를 제거한 것은 아닙니다. 이후에도 파일 보관과 메인 화면의 글 목록 연결을 구분합니다.

`index.html`을 브라우저로 바로 열어도 되고, VS Code의 Live Server 확장으로 열면 저장할 때마다 자동으로 새로고침됩니다.

1. VS Code의 확장 프로그램에서 Ritwick Dey의 **Live Server**를 설치합니다.
2. `index.html`을 열고 오른쪽 아래 **Go Live**를 누르거나, 파일을 우클릭해 **Open with Live Server**를 선택합니다.
3. 데스크톱에서 다섯 언어를 전환하며 메인 문구, 관심 분야 태그와 설명형 프로젝트 제목을 확인합니다. 기본 카드에는 짧은 요약과 본인 역할, 문제 및 결과가 보이고, “자세히 보기”에는 해결 과정 세 단계와 AI 도구 및 AI와 본인의 역할이 구분되어야 합니다. 주소 뒤에 `?lang=ko`, `?lang=en`, `?lang=zh-Hans`, `?lang=zh-Hant`, `?lang=ja`를 붙여 각 언어로 바로 열 수도 있습니다.
4. 브라우저 개발자 도구의 기기 모드에서 너비를 **390px**로 설정하고 긴 제목과 태그의 줄바꿈, 버튼 간격, 가로 넘침을 확인합니다.
5. 다섯 언어에서 Now 다음에 Contact가 이어지고, Notes 섹션과 상단 메뉴 및 빈 공간이 없는지 확인합니다. 향후 실제 글을 연결하면 목록과 메뉴가 함께 표시되는 구조를 유지합니다.
6. 상단에는 현재 언어 버튼 하나만 보이는지 확인합니다. 데스크톱에서는 마우스를 올려 목록을 열고, 모바일에서는 버튼을 눌러 언어를 고릅니다. 키보드로는 버튼에 초점을 둔 뒤 Enter 또는 아래 화살표로 열고, 위아래 화살표로 이동하며 Escape로 닫을 수 있습니다.
7. About 아래 세 개의 바가 처음에는 닫혀 있고, 오른쪽 + 또는 바 전체를 누르면 각각 독립적으로 열리는지 확인합니다. 학력, 언어와 자격, 활용 도구의 기존 내용은 펼친 안쪽에서 확인할 수 있습니다.
8. 실무 경험의 두 토글, 바이어 비교 틀과 근거 대조 흐름을 확인합니다. 프로젝트는 AXPORT와 Hanjungsun에 대시보드 버튼이 하나씩, Trade Data Lab에 서비스 버튼 세 개가 표시되어야 합니다. 보고서와 영상, 화면 자료, 개별 학습실 링크, 중첩 상세, 별도의 한계와 회고가 다시 나오지 않는지 확인합니다.
9. 연락폼의 필수 항목과 이메일 형식 검사를 확인합니다. 입력 후 언어를 전환하면 작성 내용은 현재 탭에서 유지됩니다. 새로고침하면 입력 내용은 초기화됩니다.
10. “이메일 작성창 열기”를 누르면 설정된 기본 이메일 앱에 받는 사람, 제목과 내용이 채워지는지 확인합니다. 실제 보내기는 이메일 앱의 보내기 버튼으로 완료합니다. 기본 이메일 앱 설정에 따라 작성창 연결 방식이 달라질 수 있습니다.

Notes의 사이트 내부 상대 링크는 Live Server나 배포된 사이트에서 확인합니다. 파일을 브라우저로 직접 연 환경에서는 해당 링크가 표시되지 않을 수 있습니다.

## 작성과 공개 원칙

- 제공한 이력과 성과만 사용하고 새로운 수치, 수상, 실적을 만들지 않는다.
- 숙련도를 퍼센트나 별점으로 표시하지 않고 실제 사용 범위로 설명한다.
- 팀 프로젝트는 팀 결과물과 내 기여 범위를 구분한다.
- 가운데점 기호는 쓰지 않는다.
- 입력하지 않은 링크는 화면에서 숨긴다.
- 문구를 수정할 때는 다섯 언어를 함께 수정하고, 번체는 대만식 표현을 사용한다.

## 저장소와 배포 관리

현재 사용자가 확인하는 배포 주소는 <https://portfolio-site-pi-dusky.vercel.app/>이며 Git 원격 저장소는 <https://github.com/ihappy7725/portfolio-site>입니다. 이전 GitHub Pages 주소 <https://ihappy7725.github.io/portfolio-site/>와 혼동하지 않습니다. 로컬 파일 수정, Git 커밋과 push, Vercel 반영은 구분해 확인합니다. 로컬에서 문구가 바뀌어도 커밋과 push가 전달되지 않으면 배포 화면에는 이전 버전이 남을 수 있습니다. 배포 확인은 실제 Vercel 주소에서 메인 문구와 프로젝트의 기본 및 펼친 상세, Notes 숨김을 다시 확인합니다.

로컬 Claude Code에는 별도로 `.claude/hooks/auto-deploy.sh`와 `.claude/settings.local.json`이 존재하며, 이 로컬 설정은 정적 사이트의 필수 구성 요소가 아닙니다. 해당 도구의 자동 동작은 Claude Code의 `/hooks`와 로컬 설정에서 관리합니다. 사용자가 승인한 사이트 수정은 로컬 검증, 커밋과 push, 실제 Vercel 화면 확인의 순서로 마무리합니다. 로컬 자동 훅의 존재만으로 배포 완료를 판단하지 않으며, 승인 범위 밖의 변경을 추가하지 않습니다.
