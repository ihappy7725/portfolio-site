# 정주연 포트폴리오 사이트 (portfolio-site)

HTML, CSS, JavaScript만으로 만든 한 페이지 포트폴리오입니다. 빌드 과정이 없어서 파일을 고치고 새로고침하면 바로 반영됩니다.

## 사이트의 방향

미국 국제관계 및 공공정책 대학원, 국제기구와 해외 인턴십 지원까지 계속 쌓아갈 장기 포트폴리오입니다. 국제 통상 이슈에 대한 관심을 프로젝트와 탐구 기록으로 축적합니다. 해외영업 지원용 PDF는 별도로 준비합니다.

메인 문구는 **“국제 통상 이슈를 탐구하고, AI와 협업하여 도구로 만듭니다.”**입니다. AX 과정에서 만든 업무 도구와 웹사이트는 국제 통상 이슈를 도구로 풀어낸 증거로 소개합니다.

## 폴더 구조

```
portfolio-site/
├── index.html        ← 페이지 뼈대 (보통 고칠 일 없음)
├── css/style.css     ← 디자인 (색은 맨 위 :root 변수에서 변경)
├── js/content.js     ← 모든 문구, 링크, 프로필 사진 경로 ⭐ 주로 여기만 수정
├── js/main.js        ← content.js를 읽어 화면을 그리는 코드
├── CONTENT_REVIEW.md ← 참고 자료 비교, 내용 검토 결과와 다음 보완 순서
├── prompts/          ← 다른 프로젝트에서 실행할 개발 요청문
└── assets/           ← 프로필 사진 등 이미지와 공개용 프로젝트 자료
    ├── projects/axport/axport-us-sample-report.html ← 현재 연결한 가상 기업 보고서 원본
    └── projects/axport/axport-us-sample-report.pdf  ← 이전 보고서 보관본
```

## 화면과 데이터 구조

화면 순서는 **첫 화면 → About → Experience → Projects → Now → Notes → Contact**입니다. Notes에 글이 없으면 해당 섹션과 상단 메뉴가 모두 숨겨져 Now 다음에 Contact가 이어집니다.

`js/content.js`의 `SITE.i18n` 아래에서 `ko`, `en`, `zh-Hans`, `zh-Hant`, `ja` 다섯 언어를 관리합니다. `js/main.js`가 선택한 언어의 데이터를 읽어 화면을 구성합니다.

| 위치 | 관리 항목과 표시 방식 |
|---|---|
| 첫 화면 | `hero.headline`에 메인 문구를 저장합니다. 희망 직무 표시 대신 관심 분야 태그 두 개를 보여줍니다. |
| 페이지 제목과 검색용 설명 | `meta.title`은 브라우저 탭 제목입니다. 검색용 설명은 `hero.headline` 뒤에 `meta.description`을 붙여 만들며 언어 전환 시 함께 갱신합니다. `index.html`의 기본 한국어 설명도 메인 문구를 변경할 때 함께 수정합니다. |
| 관심 분야 태그 | 국제정치경제는 `hero.politicalEconomyInterest`, 국제통상과 무역정책은 `now.interests[2]`에서 가져옵니다. `[2]`는 세 번째 항목이므로 Now 목록의 순서를 바꿀 때 함께 확인합니다. |
| About | `about.title`과 `about.body`에서 학업, 인턴 경험, 현재 AX 학습, 장기적인 탐구 방향과 대학원 준비를 소개합니다. 학력은 별도의 `about.education`에서 관리합니다. |
| 프로젝트 카드 | `projects.items`의 `question`을 요약 아래에 항상 표시합니다. 항목 이름은 “핵심 질문”입니다. 현재의 탐구 관점을 담으며 최초 제작 동기를 새로 주장하지 않습니다. |
| 프로젝트 상세 | 세 프로젝트의 `contribution`을 “내가 맡은 핵심”으로 표시합니다. 기존 `problem`, `result`, `role`, `focus`, `note`도 유지합니다. 한정선은 전체 팀 결과물과 HOME 중심의 개인 기여를 구분하며, Trade News Room은 개인 프로토타입임을 표시합니다. 값이 비어 있는 결과물과 주석은 표시하지 않습니다. |
| 상세 사례 | 선택 항목인 `caseStudy`에서 `designIntent`(설계 의도), `aiUse`(AI 활용), `artifactReview`(산출물에서 확인되는 내용), `limits`(한계)를 관리합니다. 현재 AXPORT와 한정선에 작성되어 있으며 해당 값이 있는 항목만 표시됩니다. |
| 기능 흐름과 후속 계획 | `caseStudy.workflow`는 전체 프로젝트의 기능 흐름, `caseStudy.nextSteps`는 발표 피드백과 개선 계획입니다. 한정선의 뉴스 영향 시각화는 미구현 계획으로 표시합니다. |
| 추가 자료 | 프로젝트의 `materials`에는 자료 id와 다국어 버튼 문구를, `SITE.links.projectMaterials`에는 같은 id의 주소를 저장합니다. 현재 한정선의 소개 홈페이지, HOME 시연 발췌와 홍보영상이 연결되어 있습니다. |
| 프로젝트 자료 링크 | `SITE.links.projects`는 실행 사이트, `SITE.links.reports`는 공개 보고서 주소입니다. 현재 AXPORT에 한국어 HTML 보고서가 연결되어 있습니다. 보고서 버튼의 파일 형식과 언어 안내는 다섯 언어의 `projects.labels.report`에서 함께 관리합니다. |
| Now | 현재 진행 중인 일과 관심 분야 전체 목록을 유지합니다. |
| Notes | `notes.items`의 글 목록을 최신 날짜순으로 표시합니다. 선택한 언어의 목록이 비어 있으면 섹션과 메뉴를 함께 숨기며 다른 언어의 글을 대신 표시하지 않습니다. |

프로젝트 이름은 **AXPORT | 반도체 수출 의사결정 대시보드**, **한정선 | 베트남 진출 마케팅 대시보드**, **뉴스 속 무역 공부방 (Trade News Room)**입니다. 한정선의 영문 표기는 **Hanjungsun**을 사용합니다. 기존 링크 연결을 위해 내부 `id`와 `SITE.links.projects`의 키인 `hanjeongseon`은 유지합니다.

## Notes에 새 글 추가하기

현재 다섯 언어의 `notes.items`는 모두 빈 배열 `[]`입니다. 실제 글을 준비한 뒤 다음 순서로 추가합니다. 목록을 등록해도 글의 본문 페이지가 자동으로 만들어지지는 않으므로 본문은 별도로 준비합니다.

1. `js/content.js`에서 한국어 `ko` 영역의 `notes`를 찾습니다. 프로젝트의 `note`와 구분합니다.
2. `items: []` 안에 글 객체를 넣습니다. 아래 코드는 입력 형식이며, 표시용 예시 글이 아닙니다. 제목, 날짜와 요약을 실제 내용으로 바꾼 뒤 저장합니다.

   ```js
   items: [
     {
       title: "실제 글의 제목으로 교체",
       date: "YYYY-MM-DD",
       summary: "실제 글의 한 줄 요약으로 교체",
       tags: [],
       link: ""
     }
   ]
   ```

3. 각 필드를 다음 기준으로 작성합니다.

   | 필드 | 작성 방법 |
   |---|---|
   | `title` | 실제 글의 제목 |
   | `date` | 실제 글의 날짜를 `YYYY-MM-DD` 형식으로 입력합니다. 월과 일도 두 자리로 맞춰야 최신 날짜순 정렬이 정확합니다. |
   | `summary` | 글의 내용을 설명하는 한 줄 요약 |
   | `tags` | 태그 문자열의 배열입니다. 태그가 없으면 `[]`를 유지합니다. |
   | `link` | 실제 본문으로 연결되는 `https://` 또는 `http://` 주소, 혹은 사이트 내부 HTML 파일의 상대 경로입니다. 상대 경로는 `index.html` 위치를 기준으로 작성합니다. 빈 문자열 `""`이면 글 정보는 표시하고 제목의 링크만 생략합니다. |

4. `en`, `zh-Hans`, `zh-Hant`, `ja`의 `notes.items`에도 같은 글을 추가합니다. 제목, 요약과 태그는 각 언어로 함께 작성하며, 번체는 대만식 표현을 사용합니다. 날짜는 같게 유지하고, 번역된 본문이 따로 있다면 해당 언어의 링크를 연결합니다.
5. 글이 여러 개라면 객체 사이에 쉼표를 넣습니다. 입력 순서와 관계없이 날짜가 최신인 글이 먼저 표시됩니다.
6. Live Server에서 다섯 언어를 전환하며 Notes 메뉴, 글 정보와 제목 링크를 확인합니다. 현재 언어의 목록을 다시 `[]`로 비우면 그 언어의 섹션과 메뉴가 숨겨집니다.

## 로컬에서 확인하기

`index.html`을 브라우저로 바로 열어도 되고, VS Code의 Live Server 확장으로 열면 저장할 때마다 자동으로 새로고침됩니다.

1. VS Code의 확장 프로그램에서 Ritwick Dey의 **Live Server**를 설치합니다.
2. `index.html`을 열고 오른쪽 아래 **Go Live**를 누르거나, 파일을 우클릭해 **Open with Live Server**를 선택합니다.
3. 데스크톱에서 다섯 언어를 전환하며 메인 문구, 관심 분야 태그, 프로젝트 핵심 질문과 “자세히 보기” 안의 기여 설명을 확인합니다. 주소 뒤에 `?lang=ko`, `?lang=en`, `?lang=zh-Hans`, `?lang=zh-Hant`, `?lang=ja`를 붙여 각 언어로 바로 열 수도 있습니다.
4. 브라우저 개발자 도구의 기기 모드에서 너비를 **390px**로 설정하고 긴 제목과 태그의 줄바꿈, 버튼 간격, 가로 넘침을 확인합니다. Notes 메뉴가 늘어나면 좁은 화면에서 상단 메뉴를 좌우로 스크롤할 수 있습니다.
5. 글이 없는 현재 상태에서는 Now 다음에 Contact가 이어지고 빈 공간이나 Notes 메뉴가 없는지 확인합니다. 실제 글을 추가한 뒤에는 Now와 Contact 사이에 Notes가 보이고 상단 메뉴에서 이동할 수 있는지 확인합니다.

Notes의 사이트 내부 상대 링크는 Live Server나 배포된 사이트에서 확인합니다. 파일을 브라우저로 직접 연 환경에서는 해당 링크가 표시되지 않을 수 있습니다.

## Vercel로 배포하기

1. 이 폴더를 GitHub 저장소로 올립니다.
2. Vercel에서 **Add New → Project**로 저장소를 가져옵니다.
3. Framework Preset은 **Other**, Build Command는 비워둡니다.
4. Deploy를 누르면 `프로젝트이름.vercel.app` 주소가 생깁니다. 이후 GitHub에 push할 때마다 자동으로 다시 배포됩니다.

## 작성 원칙 (Lovable 요청서에서 정한 기준)

- 제공한 이력과 성과만 사용하고 새로운 수치, 수상, 실적을 만들지 않는다.
- 숙련도를 퍼센트나 별점으로 표시하지 않고 실제 사용 범위로 설명한다.
- 팀 프로젝트는 팀 결과물과 내 기여 범위를 구분한다.
- 가운데점 기호는 쓰지 않는다.
- 입력하지 않은 링크는 화면에서 숨긴다.
- 문구를 수정할 때는 다섯 언어를 함께 수정하고, 번체는 대만식 표현을 사용한다.
- 이름은 한국어 정주연, 영어 Juyeon Jung, 간체 郑主缘, 번체와 일본어 鄭主緣으로 표기한다. 한정선의 영문 표기는 Hanjungsun이다.
- 핵심 질문과 기여 설명은 확인된 사실을 사용한다. 프로젝트 이후에 공부한 내용과 당시 직접 수행한 일은 구분한다.
- 탐구 기록에는 실제 글만 추가한다.
- 프로젝트 수행 기간, 출력물의 작성일과 분석 기준일을 구분한다. AXPORT의 프로젝트 기간은 2026년 9월이며 현재 연결한 가상 기업 HTML 보고서는 작성일 2026-11-11, 분석 기준일 2026-11-10의 출력 예시다.
- 보고서의 참고점수와 근거 반영률을 프로젝트 성과, 정확도나 수출 성공확률로 표시하지 않는다. 한국어 보고서 원본을 연결할 때는 다른 언어에서도 보고서 언어를 안내한다.
- 구현하지 않은 기능은 현재 결과물과 구분해 개선 계획으로 표시한다. 한정선 발표자료의 업무 시간 비교는 추정치이며 실측 성과로 쓰지 않는다.
- git commit과 push는 사용자가 요청할 때만 실행한다.

## 이전 버전에서 바뀐 점

- Lovable(React + 데이터베이스) 구조를 정적 HTML로 다시 만들었습니다.
- 방문자 메시지 저장과 방문자 수 기능은 데이터베이스가 필요해 제외하고, 연락은 이메일 버튼으로 대신합니다.
- 한국어, 영어, 중국어 간체, 중국어 번체(대만식 표현), 일본어를 지원합니다.
- 주소 뒤에 `?lang=ja`처럼 붙이면 해당 언어로 바로 열립니다. (ko, en, zh-Hans, zh-Hant, ja)
- 장기 포트폴리오의 방향에 맞춰 다섯 언어의 메인 문구를 바꾸고 희망 직무 표시를 관심 분야 태그 두 개로 교체했습니다.
- 세 대표 프로젝트에 핵심 질문을 추가하고, AXPORT와 한정선에는 내가 맡은 핵심 설명을 추가했습니다. 기존 상세 설명과 팀 결과물 및 개인 기여 구분은 유지했습니다.
- Now 다음, Contact 앞에 Notes를 추가했습니다. 실제 글이 생기면 섹션과 상단 메뉴가 표시됩니다.
- Experience의 근거 확인 사례와 KITA 보고서 스터디의 발제 범위를 명확히 하고, 한정선의 결과물과 Trade News Room의 개인 기여 요약을 보완했습니다.
- 참고 사이트와 첨부 가이드를 바탕으로 한 발전 방향은 [CONTENT_REVIEW.md](CONTENT_REVIEW.md)에 정리했습니다. 실제 화면, AI 협업 기록과 검증 자료가 필요한 부분은 향후 보완 항목으로 구분했습니다.
- AXPORT의 확인된 역할과 AI 사용 범위를 바탕으로 상세 사례를 다섯 언어에 추가하고, 실행 사이트와 공개 가능한 가상 기업 분석보고서 원본을 연결했습니다. 기존 팀 결과물 설명과 개인 기여 목록은 유지했습니다.
- 이후 제공된 HTML 보고서로 AXPORT의 보고서 링크를 교체했습니다. 새 파일의 근거 반영률 56%와 조건부 검토 상태, 작성일과 분석 기준일을 다섯 언어 설명에 반영했습니다. 이전 PDF는 보관하되 보고서 보기 버튼은 HTML로 연결합니다.
- 한정선의 HOME, 베트남 소개 홈페이지와 홍보영상 제작, 개인 AI 사용 범위와 추정치의 한계를 다섯 언어에 반영했습니다. HOME 시연은 팀 영상의 앞 55초를 발췌했고, 영상은 자료 버튼을 누를 때 열리도록 연결했습니다.
- 한정선의 뉴스 시각화는 후속 개선 계획으로 기록했습니다. 실제 대시보드 저장소에 붙여 넣을 요청문은 [뉴스 시각화 개발 프롬프트](prompts/hanjungsun-news-visualization.md)에 있습니다.
